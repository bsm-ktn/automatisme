Les recettes demandées par MSG

Deux automates Allen-Bradley qui se parlent : la station de mélange (L30ER) demande une recette au serveur de recettes (L32E) avec deux instructions MSG — une écriture, puis une lecture. Cette page explique le cahier des charges et comment utiliser la MSG. La solution, c'est à vous de la faire.

Le problèmeLa mise en situation

Une usine de boissons garde ses 5 recettes dans un seul automate, le L32E. La station de mélange (le L30ER) ne les a pas. À chaque lot, l'opérateur choisit une recette à l'écran.

Les quatre étapes d'un lot

  1. Le L30ER écrit le numéro voulu dans le L32E (Num_Demande).
  2. Le L32E prépare la recette (il la copie dans Reponse).
  3. Le L30ER la lit (dans Recette_Recue).
  4. Le L30ER vérifie le numéro reçu avant de s'en servir (Active).

À retenir tout de suite

Les deux MSG partent du L30ER : il écrit le numéro, puis il lit la recette. Le L32E ne fait que répondre.

Durée : 3 à 4 h. Automates : L32E 10.20.49.80 (RSLogix 5000 v20) et L30ER 10.20.49.40 (Studio 5000). Remise en équipe de deux, sur Léa.

Les quatre règles

1
Une à la foisPendant une demande, les boutons de l'écran sont ignorés.
2
Le L32E refuse un numéro hors de 1 à 5…sans s'arrêter : Reponse.Numero = 0.
3
La vérificationLa recette reçue va dans Active seulement si son Numero est celui demandé.
4
Le chien de gardeSans bonne réponse en 2 s : Defaut_Com = 1 et Active ne change pas.

RSLogix 5000 v20 · projet Recettes_L32E · 1769-L32E · 10.20.49.80Partie 1 · Le L32E : le serveur de recettes 20 points

  1. Créez le type Recette (Data Types › User-Defined), avec les membres dans l'ordre du tableau.
  2. Créez les tags du L32E. Entrez les 5 recettes dans Recettes[1] à Recettes[5].
  3. Ligne 0 : LIM 1 Num_Demande 5, puis COP Recettes[Num_Demande] vers Reponse, longueur 1.
    Ligne 1 : si Num_Demande est plus petit que 1 (LES) ou plus grand que 5 (GRT), CLR Reponse.Numero.
  4. Téléchargez, passez en Run. Écrivez Num_Demande = 3, puis 7, et regardez Reponse (essai 1).

Studio 5000 · projet Recettes_L30ER · 1769-L30ER · 10.20.49.40Partie 2 · Le L30ER : les deux MSG 25 points

La MSG, c'est l'instruction qui envoie un message à un autre automate. Ici, on en fait deux. Source et destination sont toujours vues du L30ER : il pousse un numéro, puis il tire une recette.

Essayez chaque MSG toute seule avant la séquence

Une ligne provisoire : un XIC sur un bit d'essai, puis la MSG. Forcez le bit à 1 et regardez les bits de la MSG :

DN = 1 → réussie ER = 1 → erreur
MSGMessage
Message ControlMSG_Demande
ENDNER

Quand les deux MSG marchent, effacez ces lignes d'essai.

Si ER = 1, vérifiez :
  1. le Path (onglet Communication) ;
  2. le type Recette : le même des deux côtés, membre pour membre ;
  3. que Num_Demande et Reponse sont bien des Controller Tags du L32E (pas des tags de programme).

Aussi : les deux automates dans le même réseau, le L32E en Run, le câble branché.

  1. Créez le même type Recette, membre pour membre, puis les tags du L30ER.
  2. MSG_Demande : CIP Data Table Write · Source Element Num_Choisi · Destination Element Num_Demande · 1 élément.
  3. MSG_Recette : CIP Data Table Read · Source Element Reponse · Destination Element Recette_Recue · 1 élément.
  4. Onglet Communication des deux MSG : Path 2, 10.20.49.80, 1, 0.
  5. Essayez chaque MSG seule avec une ligne provisoire (XIC d'un bit d'essai, puis la MSG) : DN = réussie, ER = erreur. Effacez ces lignes ensuite.

Dans le L30ERPartie 3 · La demande, la vérification, le chien de garde 20 points

Écrivez la séquence en ladder dans le L30ER, avec OTL / OTU, ONS, TON, RES, EQ et COP (avant la v36 : EQU et MOV au lieu de EQ et MOVE). Faites d'abord marcher les étapes 1 à 4, puis ajoutez l'étape 5.

1
Choix
Quandun bouton HMI_Rk de l'écran, sans demande en cours
Le L30ER faitNum_Choisi = k. Sur le front (ONS) : OTL Demande ; OTU Lire, Recette_OK et Defaut_Com ; CLR Recette_Recue.Numero ; RES T_Delai.
2
Demande
QuandDemande = 1 et Lire = 0
Le L30ER faitMSG_Demande envoie Num_Choisi au L32E. À son DN : OTL Lire.
3
Lecture
QuandLire = 1
Le L30ER faittoutes les 200 ms (T_Lire), MSG_Recette lit Reponse dans Recette_Recue.
4
Vérification
QuandMSG_Recette.DN, et Recette_Recue.Numero = Num_Choisi
Le L30ER faitCOP Recette_Recue vers Active, longueur 1 ; Duree_ms = T_Delai.ACC ; OTL Recette_OK ; OTU Demande et Lire.
5
Chien de garde
QuandDemande = 1 depuis 2 s (T_Delai)
Le L30ER faitOTL Defaut_Com ; OTU Demande et Lire. Active ne change pas.
Un piège : une recette est une structure. On la copie avec COP, jamais avec MOV.

Si vous avez finiLe défi

Enregistrez dans le L32E une recette changée à l'écran. Une 3e MSG (CIP Data Table Write) envoie Modif (Recette) dans Recette_Modif du L32E ; le L32E la range dans Recettes[Recette_Modif.Numero] (avec un LIM), puis remet Recette_Modif.Numero à 0.

Indices (sans la solution)
  • Le L32E doit lui aussi vérifier le numéro (1 à 5) avant de ranger : c'est le même réflexe que la partie 1.
  • Remettre Recette_Modif.Numero à 0 après la copie évite de ranger deux fois la même modification à chaque scrutation.
  • Côté L30ER : une seule MSG à la fois — attendez que la demande en cours soit finie avant d'envoyer Modif.
