L'idée en 30 secondes

Ce que c'est

PROFINET, c'est PROFIBUS qui passe à l'Ethernet.

PROFINET (PROcess FIeld NETwork) est un standard ouvert de PI (PROFIBUS & PROFINET International), porté surtout par Siemens. Il utilise le câble, les prises et les switchs Ethernet ordinaires. Première version en 2001 ; normes CEI 61158 et CEI 61784.

Dans une usine Siemens, c'est le réseau par défaut : l'automate, les E/S déportées, les variateurs, l'écran et TIA Portal passent tous par le même port.

3

Le nom avant l'adresse IP

C'est LA notion à retenir. En EtherNet/IP et en Modbus TCP, on trouve un appareil par son adresse IP. En PROFINET, le contrôleur cherche d'abord un nom. L'adresse IP vient ensuite.

1 · L'adresse MAC

Gravée en usine, imprimée sur l'appareil (sur la photo de la station ET 200SP : AC-64-17-CA-F7-60). On ne la change pas. C'est elle que TIA Portal affiche tant que la station n'a pas de nom.

2 · Le nom d'appareil

Vous le donnez une fois, avec TIA Portal ou PRONETA, par le protocole DCP. L'appareil le garde, même hors tension. Exemple : station-t.

3 · L'adresse IP

Par défaut, c'est le contrôleur qui la donne à chaque démarrage — mais seulement à l'appareil qui porte le bon nom. Exemple : 10.20.49.52.

Le démarrage, pas à pas

PLC_1 démarre et cherche la station T. Avancez étape par étape. Puis cochez « la station T n'a pas de nom » et recommencez.

Donner le nom · façon 1

TIA Portal, vue de réseau : clic droit sur la station → Attribuer un nom d'appareil → Mettre à jour la liste. Pour reconnaître la bonne station, faites clignoter ses voyants, puis Attribuer le nom.

Donner le nom · façon 2

PRONETA, l'outil gratuit de Siemens : il voit tout le réseau PROFINET, compare avec le projet, donne les noms et les adresses — même sans TIA Portal.

Donner le nom · façon 3

Automatique, par la topologie : si le projet sait quel câble va sur quel port, la CPU renomme seule une station neuve (réglages d'usine) qui en remplace une autre. Pratique pour la maintenance.

Un nom valide

Le nom d'appareil suit les règles d'un nom de domaine : lettres minuscules, chiffres, tiret ; le point sépare des parties. Pas d'espace, pas d'accent, pas de « _ ». Essayez :

Le fichier GSDML

La fiche d'identité de l'appareil, en XML : ses modules, ses paramètres, ses diagnostics. Pour Siemens (ET 200SP, S7-1200…), rien à faire : il est dans le catalogue. Pour une autre marque (îlot Festo CPX-AP-I, variateur…), téléchargez le GSDML du fabricant et installez-le dans TIA Portal : Outils → Gérer les fichiers de description d'appareils (GSD).

Et en EtherNet/IP ?

Le même rôle est tenu par le fichier EDS. Mais il n'y a pas de nom d'appareil : l'appareil est trouvé par son adresse IP (roulettes, BOOTP/DHCP ou logiciel). En Modbus TCP, pas de fichier du tout : la table de registres du manuel.

Pas de nom — ou une seule lettre de différence — = pas de communication. Le ping peut répondre quand même : il ne vérifie que l'adresse IP.
4

Le temps réel : RT, IRT et le chien de garde

PROFINET a trois façons d'envoyer une trame. Les E/S de nos stations utilisent la deuxième.

Standard · TCP / UDP + IP

Pour ce qui n'est pas pressé : charger le programme, lire un diagnostic, l'écran, le serveur web, Modbus TCP. Peut traverser un routeur.

RT · temps réel

Les E/S cycliques. Une trame Ethernet directe (type 0x8892, sans IP), marquée prioritaire : les switchs la font passer devant. Elle ne traverse pas un routeur. Tous nos appareils.

IRT · isochrone

Pour les axes synchronisés (mouvement). Chaque cycle a une partie réservée aux E/S ; le reste du trafic passe dans la partie libre. Il faut des appareils et des switchs compatibles IRT. CPU 1512SP et IM 155-6 PN HF : oui. CPU 1215C : non.

Le chien de garde, au ralenti

À chaque temps de rafraîchissement, une trame part dans chaque sens. Si la station ne reçoit plus rien pendant le chien de garde (= nombre de cycles acceptés sans données × temps de rafraîchissement), elle met ses sorties à leur valeur de repli et la CPU déclare la station défaillante. Changez les réglages, puis coupez le câble.

Dans TIA Portal : ajouter une station ET 200SP

La station T du mini-procédé, en huit gestes. Les mêmes gestes servent pour D, P et HH.

  1. Vue de réseau → Catalogue : Périphérie décentralisée → ET 200SP → Modules d'interface → PROFINET → IM 155-6 PN HF, la référence de l'étiquette (6ES7155-6AU01-0CN0). Glissez-la dans la vue de réseau.
  2. Affecter : cliquez sur « Non affecté » sous la station et choisissez l'interface PROFINET de PLC_1. Un trait vert relie la station à la CPU : elle fait partie de son système PROFINET IO.
  3. Nom et adresse : propriétés de la station → Interface PROFINET → Adresses Ethernet : IP 10.20.49.52 ; nom station-t (décochez la génération automatique du nom pour l'écrire vous-même).
  4. Les modules : vue des appareils, glissez les modules dans l'ordre réel du rail : entrées DI 8×24VDC HF, sorties DQ 8×24VDC/0.5A HF, entrées analogiques… Premier module : BaseUnit claire (nouveau groupe de potentiel) ; les suivants : BaseUnit foncée.
  5. Les adresses : chaque module reçoit ses octets (%IB5, %QB5…). Gardez le plan d'adresses ou changez-les dans Propriétés → Adresses E/S.
  6. La topologie (conseillé) : vue topologique, reliez les ports comme sur la machine (P1, P2). Le diagnostic montrera le bon câble, et le remplacement automatique deviendra possible.
  7. Compiler, puis charger dans PLC_1. Le temps de rafraîchissement reste sur « automatique ».
  8. En ligne : donnez leur nom aux stations qui n'en ont pas, puis Diagnostic en ligne : coches vertes partout, voyants RN verts sur les stations.

Le mini-procédé Festo

4 stations · 4 IM 155-6 PN HF · 1 CPU 1512SP F-1 PN
Le principe
Chaque station a ses capteurs, ses distributeurs et sa propre station ET 200SP. Un seul programme, dans PLC_1, commande les quatre par PROFINET.
Les adresses
PLC_1 10.20.49.50 · D .51 · T .52 · P .53 · HH .54 (masque 255.255.255.0).
Avant
Sans réseau, chaque capteur aurait son fil jusqu'à l'armoire. Avec PROFINET : un seul câble par station.
Le piège
Les cinq adresses doivent être dans le même réseau (10.20.49.x) : PROFINET IO ne traverse pas un routeur.

S7-1200 · CPU 1215C AC/DC/Relay

6ES7215-1BG40-0XB0 · PLC1 et PLC2 du travail 5
Rôle
IO Controller (16 IO Devices au plus) et/ou I-Device : un automate qu'un autre voit comme une station d'E/S (shared device : 2 contrôleurs).
Ports
2 prises RJ45, switch intégré, 100 Mbit/s.

« AC/DC/Relay » ne parle pas du réseau : alimentation 85–264 V AC, 14 entrées 24 V DC, 10 sorties à relais 2 A (+ 2 AI 0–10 V, 2 AO 0–20 mA). Relais = lent : pas pour des impulsions rapides.

Festo CPX-AP-I · l'îlot à deux langues

CPX-AP-I-PN-M12 (PROFINET) · CPX-AP-I-EP-M12 (EtherNet/IP)
Le principe
Des modules d'E/S et des distributeurs étanches (IP65/IP67), jusqu'à 80 modules derrière un module de bus. Seul ce module change selon le réseau de l'usine.
En PROFINET
Module -PN + son fichier GSDML dans TIA Portal : il devient un IO Device de PLC_1, avec un nom, comme une ET 200SP.
En EtherNet/IP
Module -EP + son fichier EDS dans Studio 5000 : un adaptateur du L30ER (il répond aussi en Modbus TCP).
Le piège
Même îlot, même câblage des capteurs… mais un îlot -EP ne parle pas PROFINET. On le commande avec le bon module de bus.

ET 200SP MultiFieldbus · IM 155-6 MF HF

6ES7155-6MU01-0CN0 · pour les usines « mixtes »
Le principe
La même station ET 200SP, mais sa tête parle PROFINET, EtherNet/IP et Modbus TCP.
Partage
Plusieurs chefs à la fois : jusqu'à 2 contrôleurs PROFINET + 2 scanners EtherNet/IP + 10 clients Modbus TCP.
Réglage
En PROFINET : TIA Portal. En EtherNet/IP et Modbus TCP : l'outil gratuit MFCT de Siemens (il produit aussi le fichier EDS).
Le piège
Les alarmes de diagnostic détaillées n'existent qu'en PROFINET.
Une station ET 200SP n'a pas de programme : elle obéit à son IO Controller. Le programme du mini-procédé est tout entier dans PLC_1.

Partager le réseau avec EtherNet/IP et Modbus TCP

Même câble, même switch, même plan d'adresses : oui. Même langue : non.

PROFINET, EtherNet/IP et Modbus TCP roulent tous sur Ethernet : ils peuvent partager les câbles, les switchs et le réseau. Mais partager le réseau ne veut pas dire se comprendre : une S7 ne lit pas les E/S d'un îlot EtherNet/IP sans aide.

Ce qui se partage
✓Les câbles et les prises (RJ45, M12 codage D), la vitesse (100 Mbit/s)
✓Les switchs — de préférence gérés (voir les règles plus bas)
✓Le plan d'adresses IP : tout le monde peut être en 10.20.49.x
✓Le port de l'automate : le port PROFINET d'une S7 fait aussi Modbus TCP, PUT/GET, l'écran et le serveur web — en même temps
✓Les outils du PC : ping, Wireshark
Ce qui ne se partage pas
✗La langue des E/S : PROFINET IO, CIP (EtherNet/IP), Modbus
✗Le fichier de description : GSDML, EDS, ou la table de registres du manuel
✗La façon de trouver l'appareil : un nom (DCP), une adresse IP (BOOTP/DHCP, roulettes), une adresse IP + un numéro d'esclave (Unit ID)
✗L'anneau de secours : MRP (PROFINET) ou DLR (EtherNet/IP) — un anneau = un seul des deux
✗Le diagnostic : alarmes PROFINET, état de connexion CIP, codes d'exception Modbus

S7 + Modbus TCP · le plus simple

Rien à ajouter au matériel. Dans PLC1, l'instruction MB_CLIENT reçoit l'adresse IP de l'appareil, le port 502, la fonction (lire, écrire) et la zone de mémoire. MB_SERVER fait l'inverse : un écran ou un autre automate vient lire la S7. Le tout passe par le port PROFINET, pendant que les E/S PROFINET continuent.

S7 + EtherNet/IP · trois chemins
  • Bibliothèques gratuites Siemens pour S7-1200 et S7-1500 : « EtherNet/IP Adapter » (la S7 obéit à un scanner Rockwell) et « EtherNet/IP Scanner » (la S7 commande des adaptateurs).
  • Une station ET 200SP MultiFieldbus partagée entre les deux automates.
  • Une passerelle PROFINET ↔ EtherNet/IP entre les deux mondes.

Six règles pour bien partager

  1. PROFINET IO reste dans un seul réseau local. Contrôleur et stations dans le même sous-réseau, sans routeur entre eux : DCP et les E/S RT sont des trames Ethernet directes.
  2. Un switch géré, de préférence certifié PROFINET. Il respecte la priorité des trames RT, il voit les voisins (LLDP) pour la topologie, et il se diagnostique dans TIA Portal.
  3. EtherNet/IP en multicast ? Activez le filtrage IGMP (IGMP snooping) sur le switch, sinon le multicast inonde tous les ports — y compris ceux des stations PROFINET.
  4. IRT : seulement avec des switchs compatibles IRT. Les autres trames passent dans la partie libre du cycle.
  5. Un anneau = un protocole de secours : MRP ou DLR, jamais les deux dans la même boucle.
  6. En production : un VLAN (réseau virtuel) par usage, ou des réseaux séparés. Au labo : un seul switch suffit.

Combien de place sur le câble ?

Une estimation, pour le port le plus chargé : celui de PLC_1 (ou du switch qui le relie). 100 Mbit/s, c'est beaucoup.

PROFINET RT
EtherNet/IP
Modbus TCP

Calcul simplifié, pour un sens : le câble est full duplex, 100 Mbit/s dans chaque sens. Une trame par station et par cycle, avec les en-têtes ; une question Modbus ≈ 2 trames dans chaque sens (question ou réponse, plus l'accusé TCP). L'ordre de grandeur est juste ; le chiffre exact dépend des appareils.

Partager le câble, oui ; parler la même langue, non. Pour faire dialoguer une S7 et un autre monde : Modbus TCP, une bibliothèque EtherNet/IP Siemens, ou une passerelle.

Teste-toi

À retenir

  • PROFINET = Ethernet ordinaire + PROFINET IO. Un IO Controller (la CPU), des IO Devices (les stations), un PC de mise en service.
  • Chaque appareil a trois identités : MAC (usine), nom (vous), IP (la CPU la donne).
  • Le nom avant l'IP : la CPU cherche la station par son nom (DCP). Mauvais nom = pas d'E/S, même si le ping répond.
  • Nom valide : minuscules, chiffres, tiret, point. station-t oui ; Station_T non.
  • RT = les E/S, en trames Ethernet directes : rapides, prioritaires, mais pas de routeur.
  • Chien de garde = N × temps de rafraîchissement (N = 3 par défaut). Au-delà : station défaillante.
  • TIA Portal : catalogue → affecter à PLC_1 → IP + nom → modules dans l'ordre du rail → compiler, charger → nommer en ligne.
  • En ligne, une coupure fait tomber tout ce qui est derrière. L'anneau MRP évite ça.
  • PROFINET, EtherNet/IP et Modbus TCP partagent le câble et le switch, pas la langue.
  • S7 ↔ autre monde : Modbus TCP (MB_CLIENT), bibliothèque EtherNet/IP Siemens, station MF ou passerelle.
