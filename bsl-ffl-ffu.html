    Deux mémoires, deux questions

    Le BSL répond à « où sont les boîtes ? ». La file FFL/FFU répond à « combien pèse chaque boîte ? ». Les deux travaillent ensemble.

    La même station, vue par les deux mémoiresaprès le pas 6 de la démonstration

    Le registre garde les places vides : positions 1 et 4 (bits 0 et 3 = 0). La file, elle, ne garde pas de trou : les quatre poids se suivent, du plus ancien [0] au plus récent [3].

    Une image de tous les jours

    Le BSL, c’est le plan d’un stationnement : chaque place est occupée (1) ou libre (0). Quand toutes les voitures avancent d’une place, le plan avance aussi.

    La file FIFO, c’est la file à la caisse : premier arrivé, premier servi. On ne garde pas les places vides, juste l’ordre des clients.

    Pourquoi les deux ?

    Un bit ne peut pas garder un poids : il vaut 0 ou 1. Un tableau de poids ne sait pas où est la boîte sur le convoyeur.

    Ensemble : le BSL dit qu’une boîte arrive, la file donne son poids. Et ils restent d’accord : nombre de 1 dans Pieces[0] = CTL_Poids.POS.

    Portée Controller. Sur le poste, LS1, LS2, LS3, BP_RAZ et les voyants sont des alias vers vos cartes d’entrées et de sorties.

    Exercices

    Prédisez d’abord, sur une feuille. Puis affichez la réponse, ligne par ligne.

    Exercice 1 · Suivre la station, pas par pasau départ : RAZ, tout est vide

    Exercice 2 · Quatre questions

    Pieces[0] = 2#010011. Combien de boîtes sont sur le convoyeur ? Où ? Que vaut CTL_Poids.POS ?
    Trois boîtes : positions 1, 2 et 5 (bits 0, 1 et 4). Donc CTL_Poids.POS = 3 : un poids par boîte.
    Pourquoi ne pas déclencher le FFL par LS1 ?
    LS1 donne une impulsion à chaque pas, même sans boîte. Le FFL chargerait un poids pour chaque place vide (l’ancien Poids_Balance) : les étiquettes seraient fausses. Essayez-le dans la section 1 (programme « LS1, la came »).
    Une boîte entre dans la station, mais CTL_Poids.EM = 1. Que fait le barreau 4 ?
    La branche du haut (XIC CTL_Poids.EM) allume L_Erreur. La branche du bas (XIO CTL_Poids.EM) est fausse : le FFU ne s’exécute pas, rien n’est imprimé. La mémoire et le convoyeur ne sont plus d’accord : il faut vider et faire RAZ.
    Pourquoi le BSL et la file ont-ils tous les deux Length = 6 ?
    Le BSL a 6 positions à suivre. La file doit pouvoir garder un poids par boîte : au plus 6 boîtes sur le convoyeur, donc 6 cases. Avec moins de cases, la file serait pleine (.DN = 1) et le FFL refuserait des poids.

    À retenir

    BSL = oùUn bit par position. LS1 (la came) fait avancer le registre d’une case à chaque pas.
    FFL = un poids qui entreÀ chaque boîte qui arrive (LS2), le poids va dans la case .POS, puis .POS + 1.
    FFU = le plus ancien sortÀ chaque boîte qui entre dans la station (LS3), [0] va dans Poids_Etiquette, tout avance, .POS − 1.
    Deux CONTROLCTL_Pesage pour le BSL. CTL_Poids pour la paire FFL/FFU, le même pour les deux.
    La vérificationNombre de 1 dans Pieces[0] = nombre de boîtes = CTL_Poids.POS.
    Protéger le FFUXIO CTL_Poids.EM devant le FFU ; sinon une file vide imprime 0 g.
