Un poids qui doit suivre sa boîte

La mise en situation : une balance, un convoyeur, une étiqueteuse.

La boîte la plus proche de l'emballage (1520 g) est la première pesée. C'est elle qui doit sortir la première de la mémoire.

Le problème

  • Le BSL suit des places : 1 bit par position, pièce ou pas pièce.
  • Ici, l'étiquette doit porter le poids de cette boîte, mesuré bien avant. Il faut garder des nombres, dans l'ordre.
  • La solution : une file FIFO, premier entré, premier sorti. FFL charge la file, FFU la décharge.

Comme la file à la caisse

Premier arrivé, premier servi : c'est exactement une file FIFO (First In, First Out).

2

FFL et FFU : une paire d'instructions

On les utilise toujours ensemble, pour ranger puis ressortir des valeurs dans le même ordre.

Ce qu'elles font

  • Les instructions FFL et FFU sont utilisées par paires pour stocker et récupérer des données dans un ordre prescrit.
  • Elles ressortent les données dans l'ordre de stockage : FIFO (First In – First Out), première entrée, première sortie.
  • FFL = FIFO Load : charger une valeur.
  • FFU = FIFO Unload : sortir la plus ancienne.
  • Dans Studio 5000 : onglet File/Shift, en ladder seulement.

Les bits de sortie

ENLe barreau du FFL est vrai.
EULe barreau du FFU est vrai.
DNFile pleine : .POS = .LEN.
EMFile vide : .POS = 0.

Les deux boîtes, comme dans Studio 5000Cliquez sur un opérande

Comment elles font bouger la file

FFL charger une valeur

  1. La Source est copiée dans la case .POS.
  2. .POS + 1 : la prochaine case libre avance.

FFU sortir la plus ancienne

  1. La case [0] est copiée dans Dest.
  2. Toutes les cases remontent d'un rang.
  3. .POS − 1.

Voir la file bouger, pas à pas

Chaque « suivant » = un front montant (LS2 pour le FFL, LS3 pour le FFU).

Transitionnelles : une seule action par front montant

1
Un chargement par front montant (faux → vrai). Une boîte qui reste devant LS2 ne charge qu'un seul poids.
2
Pas besoin d'ONS : le FFL garde son front dans .EN, le FFU dans .EU. Pour recharger, le barreau doit retomber à faux.

Essayez-le au banc d'essai : activez « Tenir LS2 », puis cliquez plusieurs fois sur LS2 ↑.

Dans Studio 5000, étape par étape

Les six gestes pour programmer la file (le programme est dessiné au banc d'essai).

  1. New Tag : Tableau_Poids, Data Type DINT, Dim 0 = 10 → Tableau_Poids[0] à [9].
  2. New Tag : CTL_Poids, Data Type CONTROL. Un seul, pour les deux instructions.
  3. Barre d'instructions, onglet File/Shift : glissez un FFL, puis un FFU.
  4. Opérande FIFO : Tableau_Poids[0] dans les deux boîtes. Le premier élément, sans indice variable.
  5. Length = 10 et Position = 0 dans les deux boîtes.
  6. En ligne, Monitor Tags : dépliez Tableau_Poids et CTL_Poids. Regardez .POS, .EM et .DN à chaque front.
i
Barreau 2 : RES CTL_Poids remet .POS à 0, mais ne vide pas les cases du tableau. Pour les effacer aussi, ajoutez un FLL de 0 sur Tableau_Poids.

À retenir

  1. FIFO : la plus ancienne valeur sort la première. FFL charge, FFU décharge.
  2. Un tableau du bon type (DINT[10]) et UN SEUL tag CONTROL pour la paire.
  3. L'opérande FIFO est toujours le premier élément : Tableau_Poids[0].
  4. FFL : Source → case .POS, puis .POS + 1. Une action par front montant.
  5. FFU : case [0] → Dest, tout remonte, .POS − 1. File vide → 0 dans Dest.
  6. .DN = pleine (le FFL refuse). .EM = vide (XIO .EM devant le FFU).
